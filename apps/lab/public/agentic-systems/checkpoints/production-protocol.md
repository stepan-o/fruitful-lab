# Production commission protocol

A reusable operating sheet from *Agentic systems*, directed by Stepan Oskin.
This is a proposed workflow, not an instruction to resume the closed Loopforge studio.
Use the reader’s editable commissioning sheet to name the actual job.

## 1. Define the purchase

Name the recipient, the useful difference and the present specimen. An output count is not a value measure unless it corresponds to the recipient’s use. Identify one visible action, business result or preserved obligation. Keep research questions separate from promises to implement a complete system.

Record: source/build/input, starting failure or opportunity, intended difference, protected behavior.

## 2. Set the authority and resource boundary

Name who implements, who receives the result, who resolves disagreement and who can authorize delivery. Set the actual work and review allowance before starting. Keep elapsed time, overlapping agent work, reviewer attention, external service charges and billed money distinct. Mark unavailable quantities as unknown.

A test result supplies evidence. A reviewer’s judgment has a scope. An owner’s decision authorizes a disposition. Do not silently exchange one for another.

## 3. Make a complete small slice observable

Supply the tools needed to inspect the result, not merely create source files. Verify that the receiving test can actually exercise the relevant path. Preserve rules and shared state before adding intelligent discretion. Split work only when each producer can return a clear artifact and the receiver can reject it.

For visual work, identify the target composition, device and ordinary playback rate. For data work, identify the population, source contracts and consequential error. For generated candidates, retain the proposal, evaluation and integration decision separately.

## 4. Inspect the returned specimen

Pin the exact version and conditions. Choose evidence that can change the decision: an interface trial, replay, recovery case, moving scene, held-out judgment or matched device run. Setup failure is not specimen failure. Keep false alarms, missed defects and review burden visible.

Do not infer a continuous action from sparse stills, user enjoyment from a scripted player, a final pass from an older workload, or productivity from activity totals.

## 5. Decide the marginal next step

Choose one disposition:
- Accept this bounded result.
- Repair a specific failure within the agreed allowance.
- Return a new brief because the premise or scope changed.
- Defer or stop, preserving what a successor needs.

State the useful difference expected from another increment and what it would consume. A useful investigation may end by rejecting its own proposed cause. A failed check does not automatically authorize a new job.

## 6. Close and hand over

Package the runnable result and source identity; reproduce instructions; decisive evidence; selected and excluded changes; unresolved findings; resource observations and their missing scope; decision and owner; smallest justified next brief.

Preserve failed experiments when they prevent a concrete rediscovery. Keep them distinguishable from installed or accepted work. A merge or publication does not erase a recorded failure. A new owner starts from the handoff under a new commission.
